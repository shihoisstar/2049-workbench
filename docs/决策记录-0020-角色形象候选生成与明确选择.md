# ADR-0020 角色形象候选生成与明确选择

日期：2026-10-10。范围：DRAMA-04 的首张角色形象；沿用 ADR-0019 的参考图确认入口。负责人已授权继续核心功能开发。本 ADR 不追加付费模型授权、不确定商用积分价格。

## 当前失败路径与方案

旧 candidate image 必须已有镜头候选及角色参考图，不能用于没有形象的首张生成。单纯调用旧入口会循环依赖；手工伪造素材记录会产生不存在的对象。采用现有 `drama_image_jobs` 的 portrait 目标，复用提交记录、outbox、私有资产和账本；用独立 `rolePortraitWorkflow` 保留旧候选任务历史的行为。

相比单独建一套任务系统，本方案不增加重复的计费/投递框架；代价是原 image 表新增目标互斥约束、准备内容快照和候选素材关联，旧接口需拒绝 portrait ID。媒体多保存一份引用对象，增加少量存储维护面，但避免普通上传按 hash 续期影响历史候选。迁移 0020 只在显式指定的隔离环境验收，未切换业务数据。

## 用户流程

保存角色描述 → 获取单张报价 → 明确确认 → 后台生成 → 查看本人候选 → 选择参考图 → 单独“采用此形象”。生成和选择均不自动确认角色版本。普通用户仍从角色准备页操作，不要求输入镜头编号或模型提示词。

## 任务与费用边界

- 固定项目、确认剧本版本、准备 revision、角色 key/名称/描述/用途、画风、模型、供应商绑定、3:4/1k/PNG 和报价版本。更改角色内容后旧候选不可直接选入。
- 新任务需显式开启 API、配置正整数积分与对象存储；worker 独立开关，默认 disabled。mock 仅注入验证，明确标注模拟和测试积分。真实模型固定为已研究的 `google/nano-banana-2/text-to-image`。
- 同请求键先回历史；user 锁及同角色 active 唯一约束阻止重复受理，job/outbox/hold 同事务。未知提交重试沿用请求键，不能再次 POST。
- 提交权持久化后最多一次收费 POST；已知上游 ID 持久化失败只重试本地登记。非确定拒绝保留 unknown；网络/未知 poll 响应不被当作成功或退款。
- 明确拒绝、供应商失败、completed 无输出和最终媒体发布失败，原子失败退款。unknown 禁止泛化退款；当前还没有 portrait 人工核对入口，必须补齐后才可对用户开放真实生成。
- 原始 PNG ≤10 MiB；启动解码前限制尺寸，再用 FFprobe 和 FFmpeg 校验实际尺寸/一帧。真实图至少 256 像素、3:4 容差 0.03。下载复用 HTTPS、公网 IP 固定与重定向校验。
- 原候选对象与 `materials/<user>/generated/<job>/<sha>.png` 使用相同真实字节。对象写成功后，资产、素材绑定、结算与终态同事务；生成素材沿用资产 7 天 TTL，重复登记不续期。

## 验收与后续

隔离数据库、注入供应商、真实媒体解码和 Temporal 回放结果记录于 `验收留档/DRAMA-SCRIPT-2026-10-10/ROLE-PORTRAIT.md`。未以 mock 图证明动物角色质量、真实上游协议、费用或跨镜一致性。120 次轮询后续接边界单列未验证；未知受理运营核对、微信原生操作和小额真实形象评测是开放前剩余项。
