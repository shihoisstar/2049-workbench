# ADR-0022 角色确认后的免费分镜草稿

日期：2026-10-11。负责人要求先完成未知受理核对及微信验收，再接角色确认到自动分镜，尽可能降低成本。

## 当前限制

旧镜头表以 project/episode/scene 唯一，候选仅支持一个必填角色，且旧界面手选 latest 版本。直接批量填入会丢多镜头、空景和多角色，也可能绕过已确认形象。当前解析器可复用语法和对白识别，但需保留段落原文与行号。

## 最小落地

角色准备确认后新增“整理分镜 · 免费”，按固定剧本中的动作/对白段落生成可编辑草稿。多行动作作为同一个来源段落；场景外非空文字返回具体行号，已确认项目引导到已有“复用剧本创建新项目”入口归入场景后再确认，不能静默删掉或承诺修改固定版本。角色名匹配和说话者仅为待核对建议，画外音不自动算出镜角色。所有镜头初始都待核对。

只增加 `drama_storyboard_plans` 草稿表（0022）：不可改写的来源快照、原文/行号与固定角色引用，及带revision的镜头编辑内容。sourceKey绑定剧本版本、准备revision、角色确认版本/hash和场景描述。同输入复用已有草稿，保留用户编辑；新输入创建新记录，旧记录可按ID读取，不覆盖既有画面/视频。

创建/编辑 user→project 串行，确认所有visual角色及素材有效；仅配音或无角色故事可整理空镜。镜头引用零到多个角色key，对应快照中的固定roleVersionId，不接收客户端指定版本/hash。原文、序号、场次和来源字段不可由编辑请求覆盖。编辑只改内容、出镜选择和核对状态，版本冲突保留本机文字，明确核对后才能基于新revision覆盖。

小程序按集展示，逐镜核对/修改/保存；本机允许空编辑并跨页恢复，提交仍要求非空。默认不打开技术工作台、不要求手填编号或模型提示词。

## 成本与后续

本阶段没有供应商请求、Temporal任务、报价或积分预留。额外维护面是一张草稿表和一个页面；代价是这属于规则整理，不能替代AI镜头设计、节奏/时长规划或声画对齐。多镜/多角色/空景接真实画面生成之前，还需调整旧候选引用、排序和导出边界，不能将本草稿称为已完成成片。

ADR-0021 的核对入口及微信候选流程已在此前切片实际运行；最终门禁、微信分镜操作和已知限制在本轮验收记录中留档。
