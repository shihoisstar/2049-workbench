# ADR-0015 真实剧本提交保护与回执恢复

- 日期：2026-10-10。
- 状态：按负责人确认的开发顺序实现代码；运行验收、公开报价与收费受理未完成。
- 前置：ADR-0013、ADR-0014。原有累计7次文本评测额度已用完，本轮不追加真实模型请求。

## 当前缺口与选择

旧剧本工作流对模拟activity自动重试3次，异常后直接失败；只有完成回执，没有提交前记录。直接替换成真实POST会使进程恢复时再次付费，也无法区分未受理和已受理但响应丢失。现有视频提交记录外键属于视频job，不能直接混存剧本任务。

一个剧本job只允许一次上游提交，因此复用现有drama_script_jobs行锁和outbox/Temporal，在同一行增加binding、request、submission_state、submission_token、submitted_at五列，不增加队列或通用提交框架。0016迁移为此增加约束；只生成文件，尚未应用到现有数据库。

## 实施边界

1. 内部创建真实任务时绑定Atlas文本模型与配置哈希；哈希覆盖地址、模型、路径、提示词版本/正文、token上限与关闭推理参数，不包含密钥。公开POST请求体仍只接受requestKey，HTTP仍只创建开发mock作业，客户端不能传绑定或模型。
2. 首次beginSubmission提交事务后才发起一次POST；并发/重试/重启后不重新领取。submitting或unknown不自动重发，不因超时变失败。项目保持accepted，已有唯一约束阻止重复创建同项目任务。
3. 明确HTTP拒绝标记rejected并终结；超时、网络、5xx、无效响应保留unknown。已收到但截断/空正文的规范回执仍保留用量，不当成未受理。
4. 真实回执先以原token写入response并置received；随后由receive在另一个事务内创建草稿和终结。对原回执写库做最多3次有界重试，不重复POST。后续解析/版本写入失败可从已存回执恢复。这是ADR-0014的增量：先保存上游事实，再原子发布用户可确认版本；mock原流程仍在一个事务内完成。
5. 同token同回执幂等，不同回执冲突；unknown允许原token迟到结果；已收到的结果不被迟到unknown覆盖。真实任务禁止经旧complete接口绕过回执，版本来源为ai_generated。
6. 真实activity独立单渠道文本router，90秒上游超时、2分钟activity超时；不复用视频型号或多渠道自动切换。旧mock分支保留原activity名称与超时。真实分支只核对后台，每24轮continueAsNew控制history长度；延续同一job和提交记录，内部resume只唤醒检查。
7. DRAMA_SCRIPT_PROVIDER_MODE默认disabled；只有显式atlas才读取文本配置。公开真实创建、用户报价、账本预留结算及运营核对入口仍未开放。内部准备能力不是免费公开生成服务。

## 质量与成本

提示词版本3仅制作第1集，保留项目计划集数。限制出镜角色、场景、总字数与对白长度，补充商家出杯时间/养豆天数等事实不得猜测、画外音不等于出镜形象。未再次付费评测，不能声称解决了商家事实与成片时长问题。

代价：五个持久列、真实/模拟分支与回执两段事务。若领取提交权后尚未POST就崩溃，仍可能保守进入核对；若进程在回执持久化前被杀，无法保证找回同步正文。这是防重复提交，不是供应商侧exactly-once。核对与报价完成前保持公开真实受理关闭。

## 当前验收边界

本轮只做编译、类型和静态检查，未新增或运行测试，未迁移业务数据库，未跑Temporal history replay或真机。旧243项测试记录属于之前版本，不能用于声明本轮行为已实测。后续隔离验收需覆盖并发领取、拒绝/未知/迟到回执、回执持久化故障、旧mock历史、新分支continueAsNew与前端核对状态。
