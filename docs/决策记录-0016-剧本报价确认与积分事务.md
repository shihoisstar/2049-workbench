# ADR-0016 剧本报价确认与积分事务

- 日期：2026-10-10。
- 状态：按负责人继续开发授权实现；报价与积分接入代码进入隔离验收，正式价格和真实模型调用未开放。
- 前置：ADR-0015。累计7次文本模型评测额度已用完，本轮只使用注入供应商与隔离数据库。

## 已有缺口

上一轮真实剧本拥有提交/回执保护，但没有用户确认的报价和钱包预留；原UI仍只有开发模拟入口。直接开放会产生未经报价确认的供应商费用。现有账本要求成本估计为非空数字，文本实际成本尚未知，不能用0或用户积分售价替代。

## 本轮决策

1. 复用现有billing，不新建积分系统。剧本按单集固定积分报价，本次只覆盖第1集；计划集数不扩充本次范围，画面、视频及声音不包含在此价格里。没有设置具体商用价格。
2. `GET /v2/drama/projects/:id/script-quote`只对本人项目返回报价。版本哈希绑定用户、项目、输入快照、文本供应商/模型/提示词配置和积分价。未开放时价格为null，模拟模式明确0积分。
3. 客户端只提交requestKey和quoteVersion。真实请求必须确认当前报价，不能提交价格、模型、绑定或用户ID。相同请求先查历史作业，再检查新报价；关闭受理或变更配置不会阻止原请求重放。
4. 新建事务为user→project→job→wallet，job/outbox/积分预留全部提交或全部回滚；job没有新增到reservation的即时外键。积分业务键固定为`drama-script:<jobId>`。已有作业重放读取原快照，终态不再次预留。
5. recordResponse只持久化供应商事实；received后发布草稿时同事务结算。明确拒绝、空/截断/超长输出等技术失败同事务退款；unknown保留accepted及预留，不能用普通fail或超时退款绕过核对。
6. **完整但解析失败的文本保留needs_repair草稿，同时全额退款**。用户可免费修复后确认，后续不追扣。已正常交付后仅因审美不满意而重新生成需另行报价，不伪装技术退款。
7. 成本估计字段允许显式null，保留旧视频的数值调用；比较幂等参数时不把null转换为0。真实上游账单未知仍为null，用户积分按确认的固定价格处理。
8. API和worker复用server公开的同一提示词与配置哈希函数，避免两个应用互相导入或手抄。worker仍独立显式启用文本模式；API只有`API_DRAMA_SCRIPT_ENABLED=1`且`DRAMA_SCRIPT_CREDITS`为正安全整数、文本模型/HTTPS地址有效时配置报价；默认关闭，不加载旧.env。此次没有设置这些开关或价格。
9. 小程序提交前重新取报价并确认；结果不明时按项目保存原requestKey与原quoteVersion。仅清除匹配请求；普通网络/网关5xx保留记录，不能把所有503当确定未受理。发现后端相同请求后才清理本机待确认记录。
