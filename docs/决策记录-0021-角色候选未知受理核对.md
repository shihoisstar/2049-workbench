# ADR-0021 角色候选未知受理核对

日期：2026-10-11。负责人要求先补齐未知受理核对、微信内操作，再接角色确认到自动分镜；成本优先。本轮不调用真实付费供应商。

## 当前缺口与复用

ADR-0020 保留 unknown 避免重复付费，但没有带证据恢复/退款的运营入口。现有剧本核对模式已经具备鉴权、幂等审计；image outbox 已有 resume 类型和 worker 信号。本轮复用这些模式，不新增管理后台、队列或任务框架。

新增 `/v2/ops/review/portraits` 队列及 `POST /:id` 处置，使用现有 API_OPS_TOKEN。只列 portrait accepted 的 unknown 或提交权建立超过 2 分钟的 submitting；过时判断仅决定需要核对，不构成退款证据。

## 决定与边界

- receipt 需运营明确核实任务归属，提供 provider/model/providerTaskId、原因、证据引用、requestKey；模型/供应商必须匹配冻结快照。只补登 ID，保持预留，交给原 worker 查询和验图发布。
- reject 需 confirmedNotAccepted=true 与原因/证据；拒绝、退款、审计、resume 同事务。不能凭超时或查不到结果直接退款。
- 复用 job→submission→wallet 锁序，不锁当前 user/project；运营返回最小任务状态，不依赖可能已修改的准备草稿。迟到回执不得复活退款任务。
- 同 job 只一份成功处置，requestKey 唯一且绑定规范正文哈希；同 key 同文可在终态重放，不同决定/正文冲突。审计只追加应用记录，不宣称数据库不可变。
- 0021 增加 9 列处置表，及 portrait 提交的 providerKey+providerTaskId 唯一约束，防止同一冻结供应商绑定的任务被重复挂接。不能用此约束代替人工核实供应商任务的实际归属。
- resume 与核对同事务写入既有 outbox，后台可重投；不创建新付费提交权。成功重放不再写新的 resume。
- 队列不含提交 token、完整提示词、私有 URL；普通会话不能代替运营口令，未配置则503。

## 验收

真实隔离数据库覆盖回执/退款竞争、并发同键、跨 job 冲突、迟到回执、审计失败回滚、任务编号重复、严格 HTTP 输入和默认关闭；独占 Temporal/S3 演练 unknown→核对→outbox恢复→一次结算。具体数字见本轮验收记录，不以源码完成代替运行结果。
