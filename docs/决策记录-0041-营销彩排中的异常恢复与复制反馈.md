# ADR-0041：营销彩排中的异常恢复与复制反馈

2026-10-13。负责人授权按UI/UX完整彩排、异常体验、Linux准备、真实质量方案顺序推进。先使用独立演练账户和已有样片，新增付费调用仍需单独确认。

本轮为助手流程彩排与自动化故障检查，不是普通用户可用性研究。已观察到取消确认无任务/积分预留、草稿重进与分类隔离、报价重试保留编辑、受理响应丢失后恢复原任务；H5字幕确认响应丢失后从持久回执恢复，未产生第二次结算。

需修复的四个具体问题：

1. 10秒720P固定规格遇到402时提示选择页面不存在的省钱档，并继续显示旧余额。该分支改为查看“我的”可用积分，清掉过时余额显示；旧5秒分支保留实际支持的选择。
2. 空字幕导致确认禁用和本机保存失败，泛化提示没有指出原因。操作区明确第几句为空、填写后才能确认、空行未保存；不放宽服务端字幕规则，不把无效草稿称为已保存。
3. 首次匿名身份连接失败使draftsReady一直false，编辑与底栏禁用且没有读取重试入口。新增“重新读取草稿”，沿用现有加载effect；读取未完成不再显示“先填写”来误导用户。
4. 当前Taro H5剪贴板实现未检查document.execCommand('copy')的布尔结果即可报成功。H5改为等待Clipboard.writeText明确完成，不支持/拒绝时不称已复制，而显示可手动复制的短期链接。链接有高度限制与断行，底栏按实际高度避让；微信本地保存路径不变。

H5复制失败可只提示重试，但浏览器能力缺失时重复操作无意义；选择显示链接作为实际可执行的替代。代价是失败时操作区增加一个仅本人可见的临时链接，不把链接发送给任何第三方，不持久化签名URL。没有新增生成、价格、支付、业务接口或数据库迁移。

最终门禁、两端运行结果及尚未验证的普通用户/真机事项记录于 `docs/验收留档/UX-04-2026-10-13/report.json`。不依据自动化推断满意度、留存率或普通用户成功率。
