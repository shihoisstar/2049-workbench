# ADR-0018 角色与场景准备草稿

- 日期：2026-10-10；状态：实现与隔离验收中。
- 依据：负责人确认剧本→角色确认→自动制作的顺序。

当前确认后的入口是技术分镜表单；parser.roles只是对白说话者，不能直接当出镜角色。原角色资产必须有真实参考素材及SHA-256，此前置用于一致性，不能为保存草稿而塞占位图片或放松约束。

先新增微信“角色与场景准备”页及本人项目GET/POST preparation接口。只允许固定confirmedVersionId且与activeVersionId一致的剧本。从该正文派生说话者和场次，引用最多两句对白作依据。OS/VO/画外音只检查说话者前缀，不扫描对白内容；同角色同时有普通对白时建议出镜，旁白/广播等建议仅配音。建议可由用户修改，不能当作AI视觉识别结果。

用户可选择需要形象/仅配音，补外观或声音要求、补无对白角色，给原场次补环境描述。不猜测人物年龄衣着，不擅自合并同名场景，不把一场戏自动当成一个镜头。

草稿写入项目preparation JSONB、revision和更新时间，固定来源剧本版本；保存不扣积分、不创建角色素材、分镜或视频。引用角色必须保留原名，场次标题与证据只能由后端派生；新增无对白角色使用独立键。已生成的角色资产协议保持ADR-0010。

项目行锁+baseRevision防止覆盖其他端修改；同正文重放经schema规范化，规避JSONB键排序导致的假冲突。云端已保存内容可跨设备恢复。发起保存时按项目/剧本版本备份正文和baseRevision，失败或结果未知可重进恢复；未点击保存的普通编辑仍需离开前保存，不宣称所有输入都已自动备份。

代价：项目三列、新移动页面和派生规则，不新增工作流或模型调用。主按钮为“保存准备”，不把文字草稿标为角色形象已确认。下一阶段接参考形象生成/选择及固定版本后，才进入自动分镜制作。
