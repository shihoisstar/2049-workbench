# ADR-0023 分镜草稿到图片候选

日期：2026-10-11。负责人授权继续小程序主线，要求尽可能降低成本。本切片完成单镜候选的开发模拟闭环，真实图片供应商与商业定价不开放，不追加付费授权。

## 现有路径的限制

旧镜头唯一键只有项目/集/场，候选必须有一个角色版本和一个场景版本；直接把新草稿填入会丢失同场多镜、空景、多角色，以及草稿版本隔离。旧视频/导出也无法判断所选图片是否已落后于当前草稿内容。复用任务、outbox、私有资产和钱包，扩展其输入引用；不再建一套生成框架。

## 数据与兼容

- 0023 为镜头加 plan_id 和 shot_number。旧行仍 plan_id=null、shot_number=1，旧场景唯一键保持在旧行；新行按草稿/集/场/镜头唯一，不同草稿互不覆盖。
- 新候选保存来源指纹、草稿revision、报价版本、场景/画风/画幅快照。零至十个角色版本进入带 FK 的有序关联表；来源只从草稿已确认角色读取，不接受客户端传角色版本、hash、图片或场景快照。
- 旧候选仍使用原非空角色/场景引用；新候选通过 CHECK 明确使用新快照和角色关联，不用“第一个角色”冒充多角色。旧公开DTO保持原状，旧工作台/选择/视频/导出查询限定旧镜头。新图片仍可复用本人 image-job 媒体访问端点。
- 维护代价：一张三列关联表、已有镜头/候选少量字段与新视图；不迁移旧引用，也不把新镜头静默混入旧导出。新草稿的视频与导出需要另接，当前明确不可走旧入口。

## 用户操作与费用

先保存并核对单镜，再获取报价、确认生成一张候选。API 新任务默认关闭；只有隔离装配显式启用 planImageMockAvailable 且有对象存储才接受开发模拟。每张 7 测试积分，模型标识 mock-plan-image-v1，供应商成本为 null；不是商用售价。前端始终标注开发模拟，不把占位图当成 AI 画质成果。

同用户请求键先查历史，历史重放不受开关变化影响；候选、角色引用、积分预留、图片任务和 outbox 同事务，余额不足整体回滚。同镜最多一个进行中任务，重试生成新候选，失败记录与已选图片保留。当前只使用现有 mock-candidate-image:v1 worker，不存在真实付费 POST。

只允许已发布、未过期且符合当前已核对内容的图片被选用。选择不再收费，不自动选用生成结果。编辑镜头不会自动重生成；旧图保留并标记内容已变化/曾选定。单镜内容超过3000字或出镜角色超过10个时明确要求调整，不截断或暗中减少角色。

## 验收要求

隔离测试覆盖同场多镜、双角色与空景、引用固定、报价/草稿变化、并发同键、余额不足回滚、失败退款重试、媒体有效期、跨账户拒绝和旧链路隔离。实际 Temporal/S3 验证新候选成功与存储故障退款、原选图保留和历史重放；微信页面验证报价取消/确认、重进选定与编辑后失效。

真实角色一致性、画面质量、成本和模型参数仍需后续具体小额授权评测。不能把此切片视为真实分镜生成或商业发布完成。
