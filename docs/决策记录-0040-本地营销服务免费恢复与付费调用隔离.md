# ADR-0040：本地营销服务免费恢复与付费调用隔离

2026-10-12。负责人授权按稳定性收口、UI/UX用户验收、真机环境、真实质量验证、受控试用、漫剧的顺序推进；新增付费调用先确认。

恢复前确认原试用API和两个worker已停止，专属PG/Temporal/S3容器仍运行；原库5视频、3文案均成功，没有待生成任务。旧审批文件仍有视频额度，不能把恢复原作品等同于授权新调用。现有日志没有主进程退出记录，历史退出原因仍未确定。

选择启动参数 `--live --no-paid-calls`，保留历史审批、消费记录、账户、任务、队列和对象存储。API关闭新视频/文案报价与受理；worker通过 `MARKETING_PILOT_NO_PAID_CALLS=1` 在支付网关中拒绝所有POST，允许原回执GET。原请求重放优先返回历史任务，字幕/媒体与已有作品读取继续可用。不将真实任务切换为模拟，不修改预算文件或账本。

临时改审批文件也能关闭额度，但会混淆历史授权；本方案增加一个本地恢复参数和一个worker检查，未新增供应商、业务接口、数据迁移或生产服务。默认真实模式仍须单独费用授权。已运行服务的付费模式不一致时明确拒绝第二次启动；状态文件记录supervisor PID，帮助确认主进程是否仍在运行。Windows使用独立隐藏进程及直接文件重定向保留主进程日志；不宣称已实现主进程自动恢复。

验收：`pnpm verify:isolated`退出0，53任务、384个Node测试、29缓存断言、16展示断言、14次HTTP，0失败/跳过/缓存。`work/check-live.cjs`退出0，17检查、45次HTTP、128秒、12次间隔健康采样；生成/媒体worker各一次真实进程终止后恢复，API持续可访问。原账户两作品各两次原请求重放、各一次hold/settle；新视频及文案受理返回503且未新增预留。开发者工具两作品实际重复保存，5检查、7交互，缓存文件数/字节不增加，没有注入相册或确认返回。

停止并重启整套专属服务后，原页面从连接中断提示自动恢复，无手动刷新，原账户保持。8类业务表逐行摘要一致，5份原片+5份成片大小/SHA-256一致，审批和消费文件摘要一致，新增付费调用0。证据 `docs/验收留档/LOCAL-RECOVERY-2026-10-12/report.json`。

上述是短时本地恢复验证，不证明全天/生产稳定性。手机键盘/相册、真实身份恢复、普通用户可用性研究、云端部署、新场景质量仍待验。历史退出原因尚未确定，未Git提交、推送或公开部署。

2026-10-13补充：发现快速重启时，旧启动器先清空pids再逐个停容器，后继启动可与尚未完成的容器停止重叠。停止完成标记已移到专属容器全部停止之后；容器停止失败时保留进程/诊断状态，不提前声明停止完成。实际立即停止/重启验证与本轮报告一并留档，不删除任何数据卷或消费记录。
