# ADR-0038：营销保存缓存、确认布局与试用后台恢复

- 日期：2026-10-12
- 授权：负责人要求按 B4 → B1 → B3 → 后台稳定性的顺序继续开发，新增付费调用先确认。
- 范围：本地可逆修复与固定样片验收；不新增模型调用、Git 提交、公开部署或数据库迁移。

## 已证明的失败路径

B4 曾由开发者工具 saveFile 空间超限触发，而每次保存重新下载并新增文件，错误提示混同相册权限。B1 固定底栏和安全区高度变化，已有固定留白不能保证末尾内容可达；费用说明原为行内文字，返回按钮会挤入同段。B3 已编辑输入确实用于确认/提交，但只读建议卡片未区分原稿与编辑稿。试用启动脚本在 worker 退出后关闭全部服务，且仅检查 exitCode 会漏掉信号退出。

## 实施决定

1. 开发者工具缓存按账户、assetId 和 sha256 成片版本隔离，使用 byteLength 与本地 MD5 复验后复用；签名 URL 不作为缓存身份，也不持久化。下载及持久化之间再次核验大小和摘要。已失效或损坏缓存重新下载，保留其他文件。
2. 不自动删除历史文件。用户明确点击缓存清理并确认备份后，仅删除本账户新保存功能记录的路径；云端作品、草稿、相册与未记录旧缓存保留。提示云端视频到期后无法重新下载。缓存清理失败的记录保留以便重试。
3. 下载、校验、存储空间及相册失败分别说明。手机分支仍走原生相册保存，真机权限及相册结果另行验收；H5 保留临时链接复制。
4. 营销页面测量固定底栏到窗口底部的实际遮挡高度，额外留 24px 空间，内容或窗口改变后重新测量。费用文字单独成块，返回修改按钮独立且至少 44px 高。只修改营销页面。
5. 建议卡明确只读原始建议；已采用后修改以当前输入框为准，确认/提交保持当前稿，原始回执不回写。恢复原资料前提示会替换当前修改。
6. 试用 worker 使用相同入口、环境、数据库、队列与持久额度账本重启，最多重启三次，间隔 1/2/4 秒；信号退出和启动错误同样处理。人工停止后禁止自动复活，持续失败退出并保留数据库/媒体卷。未引入新服务。

## 代价与边界

每次复用增加一次本地文件大小/摘要读取，并维护账户缓存索引。未知旧文件保留，可能仍占空间，需要先核对备份再人工清理；本次不冒称已自动治理所有历史缓存。成片版本身份取服务端 sha256，本地校验为 MD5/大小，不冒称重新计算了下载文件的 SHA-256。本地试用恢复不等于生产高可用；手机相册、多设备窄屏、长时间运行及真实供应商故障仍待验。

## 验证

完整隔离门禁：pnpm verify:isolated，53任务、383个node测试、29条保存缓存断言、0失败、0跳过、0缓存，14次HTTP。pnpm verify:worker：19份历史、315事件回放、付费0，独占容器已清理。新增 supervisor 两项测试执行真实子进程退出/信号结束及三次启动错误上限；模拟试用栈停止 generation worker 后自动恢复，API保持可访问。小程序两类固定样片流程：node scripts/verify-marketing-pilot.cjs退出0，34检查/27交互；编辑稿实际提交、底栏可达/文字按钮无重叠、重复保存不增加文件、显式缓存清理及一次结算均已验。确认弹窗及图片选择为注入；手机相册/320px设备仍未验。原录制账户两条成功作品已重新核对，临时测试栈已停止，原录制入口已恢复，付费账本哈希一致。完整门禁后费用说明/44px返回按钮样式经构建、lint/typecheck与实际UI复验；最终仅将说明样式选择器收窄，恢复3037构建退出0。
