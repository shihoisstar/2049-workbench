# 操作手册 — H5 灰度部署(单机 Docker Compose + Caddy)

> 拓扑:Caddy(80/443,自动 HTTPS)= H5 静态 + 反代 `/v1`、`/healthz`、`/videos` → api:3000;api 与 worker 同镜像;postgres/redis 内网。
> 前置:云主机(Docker 已装)、域名已解析到主机 80/443、ICP 备案状态按上线清单推进。

## 一、冷启动(新主机,约 10 分钟)

```bash
# 1. 取代码
git clone https://github.com/shihoisstar/2049-workbench.git && cd 2049-workbench

# 2. 构建 H5(本地或主机均可;产物目录 apps/miniapp/dist/h5)
pnpm install && pnpm --filter @wb/miniapp build:h5
cp -r apps/miniapp/dist/h5 deploy/h5

# 3. 生产配置
cd deploy
cp .env.production.example .env
#   编辑 .env:SITE_ADDRESS / POSTGRES_PASSWORD / JWT_SECRET / ATLAS_API_KEY / PUBLIC_BASE_URL

# 4. 起全栈(首次自动构建镜像,约 5-10 分钟;api 启动即自动执行数据库迁移)
docker compose -f docker-compose.prod.yml up -d --build

# 5. 验证
curl https://$SITE_ADDRESS/healthz          # {"status":"ok",...}
浏览器打开 https://$SITE_ADDRESS            # 模板 feed 首页
```

## 二、日常发布

```bash
git pull
pnpm --filter @wb/miniapp build:h5 && cp -r apps/miniapp/dist/h5 deploy/h5
docker compose -f docker-compose.prod.yml up -d --build   # api/worker 重建;迁移自动执行
```

## 三、备份与恢复

- 备份:`bash scripts/backup-db.sh backups`(pg_dump;建议 cron 每日)+ `tar` 打包 volume `storage`(成片)。
- 恢复:`cat backups/xxx.sql | docker exec -i <pg容器> psql -U wb -d workbench`;**注意清库重置必须连 `drizzle` schema 一起删**(迁移日志存于 `drizzle.__drizzle_migrations`,只删 public 会跳过建表——2026-10-04 实测踩坑)。

## 四、排障速查

| 症状 | 检查 |
| --- | --- |
| 白屏 | 看浏览器 console;Taro H5 生产构建吞渲染错误,先起 dev 模式复现 |
| 生成卡排队 | `docker logs workbench-prod-worker-1`;redis 队列积压 |
| 成片 404 | storage volume 是否在;`PUBLIC_BASE_URL` 是否与站点一致 |
| 生成 401/400 | ATLAS_API_KEY 过期 / ATLAS_MODEL 全路径(spec INF-04 §4) |
| Caddy 无证书 | 80/443 安全组放行;域名解析生效 |

## 五、本地预演(生产同构,已执行 ✓ 2026-10-04)

```bash
# 0. 前置:H5 构建产物 → deploy/h5;Git Bash 下 docker -v 挂载必须 MSYS_NO_PATHCONV=1
cp -r apps/miniapp/dist/h5 deploy/h5
cd deploy && cp .env.production.example .env   # 填 SITE_ADDRESS=:8099 与本地密码/KEY

# 1. 构建镜像(api+worker 同镜像;含 ffmpeg)
docker compose -f docker-compose.prod.yml build

# 2. 起全栈(端口 8099 覆盖见 docker-compose.local-override.yml)
docker compose -f docker-compose.prod.yml -f docker-compose.local-override.yml up -d
curl http://localhost:8099/healthz

# 3. 浏览器 http://localhost:8099 走真实生成冒烟
```

**预演实证(2026-10-04)**:5 容器齐活 → 注册/选款/真实生成(容器化 worker,90 秒出片)→ 自动水印 + AI 元数据 → 成片经 /videos 反代 200 → 账本三流水。
**预演抓获并修复**:compose worker 漏传 PUBLIC_BASE_URL(成片 URL 落 localhost:3010 默认值)→ 已补并对齐 api。
**注意**:Git Bash 下 `docker -v` 单斜杠路径会被 MSYS 改写(挂载静默失效,容器落默认配置)→ 一律 `MSYS_NO_PATHCONV=1` 或 Windows 盘符路径。
**停栈**:`docker compose -f docker-compose.prod.yml -f docker-compose.local-override.yml down`(数据在 volume,不丢)。

## 六、已知边界(V0)
