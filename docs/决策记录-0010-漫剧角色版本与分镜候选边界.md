# ADR-0010：漫剧角色版本与分镜候选边界

- 日期：2026-10-08
- 状态：已确定；指导 R3.2c / R3.3 的首个持久化切片。
- 关联：ADR-0005、ADR-0007、ADR-0008、R3.2b 角色一致性预研。

## 决策

1. 角色与场景均为项目内不可变版本。角色版本记录名称、描述、角色参考素材 ID 及其提交时 SHA-256；场景版本记录名称、描述。修改不覆盖旧记录，而是追加版本。
2. 每个分镜候选在创建时固定引用角色版本、场景版本、剧本版本和提示词快照；选中候选只指向一个不可变候选记录。后续角色/场景修订或单镜重做不会改写已选镜头。
3. 每次候选生成和每次单镜重做均是独立的 generation job、报价、预留与结算/退款单元；同一镜头的候选批次不共享一笔可变预留。提交使用稳定 request key，并复用 ADR-0007 的固定渠道、一次提交和未知受理处置。
4. 未知供应商受理保留预留并进入人工核对，不自动重发、不自动退款；明确拒绝或最终失败才原子退款。一个镜头失败不影响其他镜头或已成功候选。
5. 用户上传的角色原图仍受 INF-05 的既有素材留存期约束，平台不为“角色一致性”暗中延长原图留存。原图到期后，历史角色版本与已选候选元数据可审计，但不能再作为模型输入；用户必须新建绑定有效素材的角色版本。生成候选的对象生命周期沿用生成物的 7 天规则；长期导出追溯保存版本、候选、素材 SHA-256 与参数快照，而不是依赖“最新”实体或供应商 URL。
6. 首个持久化切片只接入经 R3.2b 验证的 `google/nano-banana-2/reference-to-image`，参考图字段为 `images`，最多 10 张，且始终经 `packages/model-gateway`。`bytedance/doubao-seed-character-260628` 仅返回文本，不得作为角色图像生成通道。

## 代价与边界

逐候选计费使用户能清楚对应费用与失败退款，但会增加账本、作业和候选记录数量；不能用批次成功率掩盖单次失败。到期素材不能自动重建一致性，换来不长期保存原图。首个切片不承诺多角色、视频一致性、商业授权或生产模型质量；真实付费调用只在另行限定、记录成本的验证中执行。

## 验收

- 跨账户读取、创建、选择和重做均为 404；API 主体只来自会话。
- 并发选择同一镜头只能保留一个选中候选；重放相同 request key 返回同一作业，变更载荷返回冲突。
- 角色/场景改版后，旧候选和选择仍返回原版本引用；过期角色素材拒绝新的候选受理。
- 明确失败只退款对应候选作业；未知受理不重发且不退款；单镜失败不改变其他候选。
- 真实数据库测试覆盖上述状态，worker 先以 mock 通道验证恢复；本 ADR 不构成真实模型、真机或生产存储验收。
