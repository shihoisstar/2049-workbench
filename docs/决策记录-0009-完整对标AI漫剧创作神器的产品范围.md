# ADR-0009：完整对标 AI 漫剧创作神器的产品范围

- 日期：2026-10-08
- 状态：已确定；按本 ADR 重排后续开发工单。
- 来源：负责人要求以 `docs/对标APP截图/01–29` 为功能与交互对标基准。

## 1. 决策

「2049出片」从“营销视频 + 漫剧核心闭环”扩展为对标应用**可见功能的完整等效实现**：漫剧创建、剧本库、案例/同款预填、营销带货与探店、作品与下载、账户/设置/反馈、协议与权益入口，以及可审计的付费能力。

“完整对标”是用户可达能力、状态和交互闭环的等效，不是复制对方名称、图标、视觉资产、示例素材、条款、数据、收益宣传或实现代码。UI 保持「2049出片」自有视觉与文案；截图只作为可见行为证据，截图外行为不得臆定。

## 2. 不被对标覆盖的产品规则

以下现有规则优先于对标应用的可见做法：

1. 成片始终保留可见 AI 标识和元数据标识；任何“无水印”权益不得移除法定或产品要求的 AI 标识。
2. 积分不过期；报价、预留、结算/退款和不可变流水继续以 contracts 与账本不变量为准。
3. 明确失败即时退款；未知受理不自动重复提交或退款，进入人工处置。
4. 不实现伪造倒计时、虚构收益、购买播报或无法服务端核验的权益。
5. 用户协议、隐私、自动续费和退款页面只编写「2049出片」自身经确认的内容，不复制参考应用文本。

## 3. 范围与缺失证据

纳入范围：

- 双模式漫剧创建、云端项目/剧本版本/剧本库、角色场景、分镜候选、逐镜重做、配音字幕合成与导出；
- 模板/案例浏览、创作同款预填及明确的覆盖提示；
- 营销带货/探店表单、真实素材上传、AI 文案、报价、生成、作品与重复下载；
- 游客与已验证账户、设置、反馈、分享、缓存管理、协议入口、权益展示及付费能力。

29 张截图不能证明角色编辑细节、生成恢复、镜头重试、支付、订阅扣费、导出、模板授权和注销后的资产处置。它们必须先由需求、契约与后端能力定义，再作为本产品行为验收；不得把推定当作对标事实。

## 4. 实施次序

1. 更新需求池，移除“模板市场/创作同款/会员优先队列”作为明确不做的限制，并建立范围验收口径。
2. 在新功能扩展前完成已实现营销链路的真机风险验证。
3. 先实现漫剧项目、剧本版本、解析/人工修复和剧本库，再进行角色一致性评测；没有质量与成本结论，不建设跨镜复用承诺。
4. 依次建设角色/场景版本、分镜候选、逐镜生成与重做、配音字幕合成和可追溯导出。
5. 在核心事实源稳定后补模板同款、账户设置、协议、作品管理和权益界面。任何订阅、优先队列或权益执行均须先有合同、服务端判定和一致性测试。

## 5. 验收边界

每一项纵向切片均须先落 contracts、迁移和公开模块入口，再接 API/worker/miniapp；前端不得以示例数据伪装已实现能力。需要真实模型、支付、微信认证或生产存储的能力，明确拆分为本地模拟验收和外部依赖验收。所有提交继续以负责人明确口令为条件。
