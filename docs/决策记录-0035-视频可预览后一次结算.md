# ADR-0035：视频可预览后一次结算

2026-10-11。负责人明确回复：“接受，视频可预览后结算”。该回复只授权收费规则变更，不授权新增模型付费调用。

## 实际问题与最小实现

原生营销视频已经生成并私有保存时，旧规则仍等待用户确认字幕、完成导出才结算；用户长期不回来会一直占用预留。沿用既有预留/结算账本，不新增收费动作或第二张订单。

新10秒营销任务的报价及任务冻结settlementPoint=preview。只有媒体工作进程检查原片大小、时长、画幅、H264/AAC并成功写入私有对象后，capture事务才保存来源、结算原预留、记录actualCredits。作业可以继续处于accepted等待字幕，但积分已结算；输出成片才标succeeded。视频生成失败仍由既有路径退款；未保存成可预览原片的存储失败保留预留以便恢复，不提前结算。

确认字幕、识别重试、合成重试和导出只使用原任务/原片，不再预留或结算。已结算的视频不允许被字幕错误误转成“视频生成失败”而退还制作费；继续提供原片预览与免费恢复入口。退款纠纷/人工补偿另走后续运营流程，不篡改已结算流水。

`0032_amazing_cammi.sql`增加native_billing_point。历史记录保留null并解释为export，继续按原成片规则结算，不追溯改变已有任务；新报价指纹加入结算时点，旧的未受理报价需重新确认。旧5秒和漫剧既有账本逻辑保持原规则。普通用户请求不能选择结算时点。

## 页面

- 提交前说明“视频可预览后结算一次”，包含原声、字幕及合成。
- 原片未就绪显示“已预留”；原片保存成功后显示“已消耗”，并说明字幕修改/合成重试免费。
