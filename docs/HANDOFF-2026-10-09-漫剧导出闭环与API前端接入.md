## 6. 关键技术语义速查

### 6.1 Export manifest 与可追溯性

`DramaExportManifest` 每镜保存：shot/candidate/script/role/scene version IDs、source video job/asset ID、object key、SHA、长度、宽高、时长。创建 export 后 source selection 的后续变化不影响它。`manifestSha256` 用 canonical JSON（对象 key 排序、array 原顺序）算 SHA-256。

### 6.2 job 与 outbox

```text
ExportJob status: accepted -> succeeded | failed
workflow ID: drama-export:<jobId>
outbox events: drama_export.requested / drama_export.resume
outbox: at-least-once claim (30s lease) / ack / exponential release
```

start/ack 之间丢响应时 redelivery 用同 ID；starter 捕获 `WorkflowExecutionAlreadyStartedError` 后 verify workflow type；wrong type must throw，不能吞。

### 6.3 object-store boundary

合法 export key 必须：

```text
drama-export-jobs/<uuid>/<64 lower-hex sha>.mp4
```

合法 shot-video key：

```text
drama-shot-video-jobs/<uuid>/<64 lower-hex sha>.mp4
```

任何尝试通过 URL、路径遍历、任意 bucket key 读取都必须被 object-store allowlist 拒绝。FFmpeg 只读本地 temp files，不能拿 S3/HTTP URL 给 ffmpeg。

### 6.4 导出失败为何 activity 返回 terminal

旧版 flow 在 activity 内已 `fail()` 后 rethrow，而 workflow retry policy 会调用 3 次，后续 activity 看到 durable failed job 仍会错误重试并让 workflow failure。当前实现的正确语义：

```ts
catch (error) {
  await services.dramaExports.fail({ ...input, failureCode: 'EXPORT_COMPOSITION_FAILED' });
  console.error(JSON.stringify({ event: 'drama_export_composition_failed', ... }));
  return { jobId: job.id, status: 'terminal' as const };
}
```

这不等于静默：有 durable job failure code + structured log + runtime replay evidence。不要把它改成吞全部异常；若 `fail()` 本身抛错，activity 仍会抛，以便 Temporal 重试暂态 DB 故障。

### 6.5 当前 mock 的范围

- 逐镜视频：内联 H.264 MP4，`240x426`、`5000ms`、3904 bytes，已带 AI 标识；仅 mock。
- export：FFmpeg concat + ASS `第N场` 字幕 + `AI生成 · 2049出片` + silent audio；测试验证一个镜头输出约 `10133 bytes/5000ms`。
- 不代表“60–120 秒真实成片”已产品验收；R3.4 spec 仍是“开发中”。
- 不代表真实 TTS、真实图像/视频 provider、真实手机已验证。
