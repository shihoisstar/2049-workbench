# ADR-0006：新身份与账本事务边界

- 日期：2026-10-06
- 状态：已实施，随REBUILD-01验证；不代表旧系统已切换。
- 上位决策：ADR-0005；关联INF-01、INF-02、BIZ-05、R2.1。

## 触发与范围

旧实现3项钱包缺陷已有真实数据库复现：并发入账丢余额、并发预留透支、退款后再结算重复退差。新实现放在packages/server，通过独立的wb_next表与v2端点验证，不对历史流水做重算或覆盖。

本轮交付游客会话、钱包查询、注销，以及仅服务端可调用的grant/reserve/settle/refund。微信绑定、真实支付、任务受理与预留的联合事务、数据迁移另行实施。

## 决策

1. **身份凭据与设备标识分开**。v2游客登录接收客户端CSPRNG生成的256位秘密凭据（64位小写hex），服务端仅存SHA-256。禁止以Date.now/Math.random或公开deviceId代替。API只能检查格式，客户端生成质量需在前端接入时验证。
2. **会话可撤销**。返回32随机字节的base64url token，仅存哈希，以数据库时间计7日有效期。旧JWT不被v2接受。注销撤销全部会话，保留注销标记，原凭据不能重新领取赠送。
3. **注册原子性**。identity/bootstrap、session、wallet和80积分赠送在一个事务内；并发同凭据只创建一个账户并赠送一次。该保证不等于防止批量生成新凭据薅免费层，生产防滥用仍需完成。
4. **显式数据所有权**。schema.ts是单一迁移装配文件，仅集成人修改；Drizzle生成DDL和迁移元数据。模块内的参数化SQL明确表示锁和更新顺序，原始事务只在服务端基础设施装配层流转，public.ts不暴露它。
5. **串行化同一钱包**。新增资金/预留先锁身份再锁钱包；状态与幂等检查在钱包锁内完成。已预留资金的结算/退款不要求账户仍活跃，注销不能使冻结资金无法终结。
6. **预留单一终态**。reservation保存held/settled/refunded。相同参数重放不重复写流水，不同参数报409；数据库部分唯一索引额外禁止同一预留出现settle和refund两条终结记录。
7. **金额范围包含退款能力**。所有金额用安全整数；入账前以BigInt核对“可用余额+全部held+新入账≤MAX_SAFE_INTEGER”。仅检查当前可用余额会在极端金额下使后续退款失败，该路径已先复现再修复。
8. **不可变流水**。数据库触发器拒绝流水UPDATE/DELETE。余额非负、金额符号、预留状态和所属外键同时受数据库约束；余额等于流水和由事务写入及并发测试维护，不冒称数据库自动强制聚合相等。
9. **读取与权限**。/v2/wallet只按已认证会话主体查询，不接受用户ID作为主体；余额与最近20条流水在同一repeatable-read快照读取。新API没有任意加减积分端点。
10. **测试先确定目标库**。gate拒绝缺失、远程、普通开发库或彼此不一致的测试连接；verify:isolated创建自己的DB/Redis。新服务集成测试关闭Turbo缓存，隔离运行器强制全部任务重新执行，不能以skip或旧缓存宣称通过。

## 代价与未覆盖部分

客户端需妥善保存游客秘密凭据；丢失凭据的账户恢复需要未来绑定身份能力。注销保留的哈希与财务记录保留政策在发布前需与协议一致。

同钱包写入串行化限制该账户的并发吞吐，但不全局锁住所有用户。入账需要计算当前held合计；高负载下需测量查询计划后再优化，不能取消退款能力检查。

新旧表并存仅为迁移阶段；没有自动复制历史余额。会话与凭据迁移、真实订单回调、生产访问控制/限流和上线切换尚未完成。

## 验证证据

独立PostgreSQL执行18项服务集成测试：50路同凭据注册、50路充值、50路预留、同键重放、退款/结算竞争、金额上限、数据库错误回滚、注册中途失败全回滚、注销与登录/消费同时竞争、会话哈希/过期及不可改流水。新API另有6项账户HTTP集成测试和8项基础测试。完整gate结果记录于REBUILD-01。
