2026-10-12。负责人要求同步深入分析 UI 与 UX，覆盖步骤、信息密度、操作、等待、异常及更多问题，并按营销稳定性→真机→真实质量→受控试用的次序继续。当前首版为剧情带货与探店；漫剧不在本轮扩展范围。

## 用户任务与设计判断

用户的核心任务是把商品/店铺资料变成可保存的视频，并始终知道当前稿件、下一步操作、费用及恢复办法。现有功能链路能执行，但页面更接近开发功能的排列：宣传标题→素材→长描述→完整AI原稿→参数→费用；进度、字幕与结算则按后端状态分别呈现。

两种实施范围都可行：在原排列中补提示，成本小；在现有架构内按任务重组四屏，改动较多但能一起解决层级、重复信息和下一步问题。本轮采用后一种，沿用暖白/炭黑/荧光黄绿、Taro 双端和已有接口。没有新增模型、字体服务、图片资产、业务收费动作或后台契约。

## 信息结构与状态规则

创作：当前步骤→真实资料/可选素材→当前制作稿→可选文案助手→时长提醒→下一步核对。确认：当前稿与素材→规格→本次报价与费用边界→明确确认。制作：真实阶段→当前主操作→原视频/字幕→费用与恢复说明。作品：分类/阶段→可辨识内容→创建时间/规格→计费事实→继续动作。我的：可用积分→预留与结算解释→不可变明细。

原始资料、AI原稿、当前编辑稿、已确认字幕及已保存成片不能混称。accepted不是一个完整的用户状态；actualCredits不为空也不等于最终成片完成。报价获取、刷新、字幕重读不触发新的模型生成；重复确认保持原请求和回执。没有准确百分比或真实耗时数据时不展示虚构进度/倒计时。

## 验收目标

1. 320/375/430及桌面H5检查横向溢出、字号、必填输入、固定栏及点击区域；窄屏步骤允许换行而不缩成不可读小字。
2. 原稿折叠/展开不改当前稿，刷新报价不覆盖编辑；恢复资料仍需确认。
3. 视频生成、字幕准备、待核对、后期处理、可保存、失败及媒体恢复均能识别下一步；待核对阶段的主操作在可视区。
4. 字幕修改、离开/重进、一次确认、成片保存、重复保存与账户隔离完整回归；保存结果不需再次滚动寻找。
5. 积分结算零差额不是绿色“+0”，设备本地时刻正确，原账本/扣费规则不变。
6. 覆盖初次加载、空作品、连接失败、权限/文件空间、额度不可用与过期。手机键盘、相册、真实账户恢复保留未验标记。

阶段结果与命令/数字在本轮验收报告记录，不沿用上一轮数字。下一阶段先用这些页面做一次无助手口头指导的普通用户任务测试，再依据实际卡点迭代；同时继续免费稳定性验证及私有真机环境准备。新增真实调用仍须单独明确次数与预算并获批。
