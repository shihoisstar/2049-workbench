## 视觉基线

这些值是可执行设计的起点，不声称从生成图片精确反推了原始Figma参数；实际页面截图验收时允许统一微调。

| 项 | 基准 |
| --- | --- |
| 背景 | 暖白 #F7F7F5；卡片 #FFFFFF |
| 主文字/暗卡 | 炭黑 #171719 |
| 次要文字 | #66666E，避免正文过浅 |
| 主操作/选中 | 朱红 #D92336；浅红背景 #FFF1F2 |

| 圆角 | 控件8、卡片12、重点媒体16；主操作不使用超大胶囊 |

| 触控与安全区 | 核心操作不小于44逻辑像素；底栏预留设备安全区 |

## 组件与页面

先实现带加载/禁用/错误状态的按钮、输入框、选项组、作品卡、状态标签和底部操作区，再组合页面。营销、漫剧、作品、钱包各自有feature入口；不再在单页按mode无限叠加逻辑。

先以375逻辑宽度作为Taro设计基准，检查320/375/430及桌面H5宽度。H5在宽屏限制表单宽度、调整卡片列数，避免把手机布局横向无限拉伸。保留一个小程序/H5工程，不新增第二套面向用户的Web工程。

参考图中的作品图是视觉内容示例，不能把整张UI截图贴成页面。生产页面由真实组件构成，封面使用独立素材或实际生成作品。没有实现的漫剧能力不得伪装成已可用。

## 验收

每条业务闭环完成后，对实际H5截图与参考板比较排版、文字层级、封面占比和主操作位置；微信运行时单独检查输入、上传、滚动、相册权限与底部安全区。

截图之外还要覆盖加载、空数据、网络失败、余额不足、生成失败/退款、到期和授权拒绝。参考图中的日期、价格、上传限制、假进度不能覆盖契约；用真实状态取代装饰性百分比。
